## 建议采纳的 5 条核心规则（来自原工程）

### 规则 1 · 断签不清零
单日未打卡**不影响"累计总天数"**。累计 = 真实打卡天数 + 导入天数（如果有导入）。
总天数只增不减。

### 规则 2 · 连续数：漏 1 不断，连漏 2 暂停
- 今天已完成（打卡或休息）→ 连续数 +1 起步
- 向前遍历历史节点：完成 → +1
- 漏签第 1 天 → **连续数不变**（不断）
- 连续漏签第 2 天 → **暂停，立刻停止遍历**（不归零）
- 恢复打卡后从暂停点继续 +1，不回到 0
- 例：连打 10 天 → 漏 1 天（仍是 10）→ 再漏 1 天（暂停，仍是 10）→ 打卡（变 11）

### 规则 3 · 历史最长连续永久保存
`bestStreak` 一旦产生就永久保留在记录里，即使之后断签、即使重装（前提是数据在本地）。
任何时刻显示的最长连续 = max(历史记录值, 当前连续)。

### 规则 4 · 补签时间窗 = 过去 7 天
- 只能补 **1~7 天前**的打卡（今天和超过 7 天的不补）
- 补签只生成"打卡"，**不能把过去的某天改成休息日**
- 该天已标记休息日的，不需要补签（也不能补）
- 早于习惯创建日的不能补

### 规则 5 · 休息日只能事前或当日标记
- 可以标记今天、未来任意一天
- **历史日期禁止**标记休息（避免回溯篡改）
- 已标记休息日可以被改回打卡
- 休息日在连续统计里等同于"完成"，不算漏签

## 周期节点模型（原工程的"频率 N + 窗口次数"）

这套是 原工程v0.2 相对旧版的最大改动，现 index.html 没有：

- **频率 N（1~30，默认 1）**：一个圆环节点代表 N 天
- **窗口次数（1~20，默认 1）**：一个周期窗口内要打几次才算达标
- 节点从**习惯创建日**起算，**不对齐自然周**
- 节点状态判定优先级：窗口内有打卡 → `done`；窗口内有休息日 → `rest`；否则 `miss`
- 节点旁显示 `3/8` 这样的进度；**但节点"实心"只看窗口内是否至少打卡 1 次**，不是看满次数
- 圆点渲染：7 点一圈逐圈外扩，**只有相邻节点都实心才连线**

## 可视化与交互规格

| 项 | 规格 |
|---|---|
| 首页卡片 | 名称 + 当前连续 + **最长连续** + 最近 7 天迷你点条（无圆环、无曲线） |
| 螺旋圆环 | 7 点一圈、逐圈外扩、相邻实心才连线 |
| 横向累计曲线 | 只增不减；漏签段转**点状虚线**；每 5 天一个刻度 |
| 首次引导 | 首次打开圆环顶部显示引导小字，操作一次后不再显示 |
| 颜色规则 | 打卡柔和青绿 / 休息浅灰蓝 / 漏签底色；**禁用红色**（避免压力感） |
| 仪式两层 | ①弧段闭合 → 呼吸 1 秒 ②刷新最长连续 → 光晕 + 顶部小字 3 秒。多层同时触发只走最高层；补签不触发；无音效无弹窗 |
| 免费上限 | 5 个习惯，第 6 个温和提示一次，不反复弹 |
| 成就卡内容 | 该习惯圆环/曲线 + 名称 + 最长连续 + 累计周期数 + 备选文案 + 自定义签名 |

## 移植到 index.html 的注意事项

1. 现 index.html 的连续统计如果要改，必须同时改**展示**和**持久化**两处，否则冷启动会回退。
2. `bestStreak` 要写进 localStorage 的一个独立键，不能用"当前连续"临时算。
3. 规则 2/3/4 都会改变已有用户的数字，属于**行为变更**，不是纯 bugfix，改之前想清楚要不要保留老算法做兼容。
4. 原工程的这套逻辑有 28 个 jest 用例覆盖，移植时建议照抄同样的用例结构。
