# RockSort 代码审查机制（系统化审查标准 + 流程 + 铁律）

> 目的：把"逐次靠经验审查"升级为"可复用、可交接、可自动化"的固定机制。
> 适用范围：RockSort 及同栈（Expo SDK 55 / RN 0.83 / New Architecture / 秒哒 devkit）的所有 App。
> 作者：代码审查专家（火眼眼）｜建立于 2026-09-19

---

## 一、问题分级标准（铁律：先分级，后描述）

| 级别 | 含义 | 处理要求 |
|---|---|---|
| 🔴 **阻断（Blocker）** | 崩溃 / 数据丢失 / 安全漏洞 / 上架被拒 / 破坏既有功能 | 合并前必须修复 |
| 🟡 **应修（Suggestion）** | 隐藏 bug 风险 / 明显可维护性 / 性能浪费 / 合规隐患 | 本迭代内修复或留 TODO 并排期 |
| 💭 **建议（Nit）** | 命名 / 注释 / 风格一致性 / 轻微冗余 | 顺手改，不阻塞 |

**格式铁律**：每条评论必须含 ①位置（文件:行）②为什么 ③具体建议。禁止只写"这里有问题"。

---

## 二、审查流程（5 步，可交接给秒哒 / 任意 AI 工具）

1. **静态扫描（机器先跑）**：用本机制附带的 `audit-scan` 脚本，先扫出 `console.log`、裸 `any`、未捕获 `await`、死代码 import、启动期原生调用等。
2. **预审（读改动 diff）**：只审本次变更行；确认"执行起来发生什么"，不只"字面上写了什么"。
3. **重点走查（按本机制的清单逐维度）**：正确性 > 安全 > 可维护 > 性能 > 测试。
4. **真实性核对（AI 生成代码的生死线）**：
   - 凡涉及原生模块、启动路径、深链、支付、通知，**必须**运行/打包验证，不能只信源码注释。
   - 崩溃类问题必须解析 `.ips` / 设备控制台 `reason:`，不能靠猜。
5. **终审交付**：一份报告，含分级清单 + 亮点 + 已修复核对 + 下一步。

---

## 三、审查检查清单（逐维度，逐文件打勾）

### 正确性
- [ ] 边界：空数组 / 空字符串 / undefined / NaN 是否被兜住？
- [ ] 异步：原生 `await` 是否都在 `try/catch` 内？Promise 是否有失败分支？
- [ ] 状态：stale closure（setState 后立刻读旧值）是否存在？
- [ ] 持久化：写入快照是否覆盖所有被改字段（防丢数据）？

### 安全 / 合规（出海必查）
- [ ] 隐私政策：代码与线上文案是否一致？是否禁用内嵌 WebView？
- [ ] 内购：价格是否零硬编码（走 App Store 后台）？演示态是否不静默解锁 Pro？
- [ ] 用户输入：CSV / 文本是否做长度与格式校验？

### 可维护性
- [ ] 单文件是否超 400 行（超则拆，如本工程把 `store/app.tsx` 630 行拆为 4 模块）？
- [ ] 死代码：是否有零引用的文件 / 导出（如本工程 `theme.ts`、`components/ui/*`）？
- [ ] 重复：是否同一逻辑写了多份（如重复请求 Offerings）？

### 性能
- [ ] 启动期是否触碰原生模块（iOS 26 + RN Release 的 TurboModule 崩溃陷阱）？
- [ ] 列表 `.map` 是否缺 `key`？`key={i}` 是否可接受（静态列表才接受）？
- [ ] `useMemo` / `useCallback` 依赖是否完整？`useAnimatedStyle` 是否只在 UI 线程？

### 测试
- [ ] 核心算法（评分 / 日期 / CSV 解析）是否有单测且覆盖边界？
- [ ] 关键路径（支付 / 导入 / 持久化恢复）是否在真机验证？

## 四、RockSort 工程铁律清单（已知不可犯规则，沉淀自历次 review）

1. **冷启动零原生调用**：启动路径（`_layout` / `index` / 全局挂载 / `ModalHost`）不得同步调用会抛异常的原生模块。iOS 26 + RN Release 下，原生 void 方法抛 `NSException` 会 `abort` 整个进程，JS `try/catch` 兜不住。
2. **RevenueCat 懒加载 + 门控**：`Purchases.configure` 仅在 Pro/Pay 弹层真正打开时（`enabled` 门控）才调用，绝不在启动期。
3. **深链中性化**：`Linking.getInitialURL` / `getLinkingURL` 覆盖为返回 `null`（本 App 无深链需求），同时根治 Unmatched Route。
4. **价格零硬编码**：所有价格展示位用占位符，数值运行时从 RevenueCat Offerings 读；演示态需 `EXPO_PUBLIC_DEMO_IAP=1` 才允许解锁。
5. **日期本地化**：禁止用 `toISOString()` 当日期字符串；一律 `YYYY-MM-DD` 本地时区。
6. **连续打卡差一**：`calcStreak` 从"今天已打卡计 1，昨天 i=1 起算"，不得从 i=2。
7. **完成延迟写入**：勾选完成 400ms 延迟写回，期间先触觉 + 撒花反馈。
8. **左滑互斥**：通过 `swipeBus` 单例广播；新行展开旧行收起；280ms 时间窗吞掉手势后误触。
9. **弹层统一管理**：8 弹层由 `ModalHost` 挂载；Pro/Pay 共享一次 Offerings 请求。
10. **可访问性**：所有可点元素带 `accessibilityRole` / `accessibilityLabel`；44pt 触控热区。
11. **状态恢复防御**：`useHydration` 对损坏数据（非数组 / 缺字段）做 `filter` 兜底，绝不崩。
12. **镜像 UI 线程守卫**：Reanimated `onUpdate` 每帧 `runOnJS` 必须先用 shared value 判越阈，一次性跨线程。
13. **通知权限时机**：首次添加带提醒任务时才 `requestPermissionsAsync`，不在启动期弹。
14. **删除即取消通知**：`doDelete` 必须 `cancelTaskReminder`，不残留。
15. **导出成功提示在 try 内**：不得写在 try/catch 外（否则失败也报成功）。
16. **不得引入假入口**：导出/分享不得有邮件/微信/隔空投送等点开只弹 toast 的演示入口（审核风险）。
17. **保持 devkit 栈锁定**：不得降级 Reanimated 到 v3（秒哒 `miaoda-expo-devkit` 硬依赖 `react-native-worklets`）；iOS 26 崩溃用 reanimated 4.6.0 + worklets 0.12.2 修复。
18. **i18n 完整性**：`Dict` 两语言 key 必须一一对应；建议启动时断言校验，避免渲染 `undefined`。

## 五、自动化扫描脚本（可运行）

放到工程根 `scripts/audit-scan.mjs`，CI / 提交前跑：

```js
// scripts/audit-scan.mjs —— 轻量静态扫描，定位常见反模式
import { readdirSync, readFileSync, statSync } from "node:fs";
import { join } from "node:path";

const SRC = "src";
const issues = [];
const walk = (dir) => readdirSync(dir).flatMap((f) => {
  const p = join(dir, f);
  return statSync(p).isDirectory() ? walk(p) : [p];
});

for (const f of walk(SRC).filter((f) => /\.(ts|tsx|js|jsx)$/.test(f))) {
  const src = readFileSync(f, "utf8");
  const L = src.split("\n");
  L.forEach((line, i) => {
    const n = i + 1;
    if (/console\.(log|debug)/.test(line)) issues.push(`[console] ${f}:${n}`);
    if (/:\s*any\b|as any|any\[\]/.test(line)) issues.push(`[any] ${f}:${n}`);
    if (/await\s+[^(]*\([^)]*\)\s*;/.test(line) && !/try/.test(L.slice(Math.max(0,i-3),i+1).join("\n")))
      issues.push(`[await-no-try] ${f}:${n}`);
  });
}
// 死代码：扫描未被任何文件 import 的导出（示例：theme.ts）
console.log("=== 静态扫描结果 ===");
console.log(issues.length ? issues.join("\n") : "无常见反模式");
```

> 真机 / 崩溃类问题无法靠静态扫出，必须走"真实性核对"第 4 步。

## 六、与 AI 工具（秒哒）协作的交接模板

把以下提示词发给秒哒，让它按本机制产出修复：

```
请按 RockSort 代码审查机制（docs/代码审查机制.md）的铁律与清单修复以下问题：
【粘贴分级问题清单】
要求：
1. 每条修复后说明"执行起来发生什么"，不只改字面。
2. 涉及原生 / 支付 / 通知 / 启动路径的改动，必须给出真机验证步骤。
3. 不降级 Reanimated 到 v3（devkit 锁定 worklets 栈）。
4. 改完列出改动文件清单与行号。
```

## 七、本机制自身的维护

- 每次发现新的"不可犯规则"或新反模式，追加到 **第四节铁律** 与 **第五节脚本**。
- 每半年回顾一次检查清单是否仍贴合技术栈（Expo / RN / iOS 版本升级时必回顾）。
