## 二、应修问题（🟡）

1. **`lib/notify.ts:48` — 取消通知多余请求权限**
   `cancelTaskReminder` 内 `await requestNotifPermission()` 多余：取消已调度通知不需要用户授权，且用户若之前拒绝过，这里会再次触发系统授权弹窗打扰。
   **建议**：删除该行；权限仅在 `scheduleTaskReminder` 调度时申请一次即可。

2. **`components/TaskRow.tsx` `onEdit` — 互斥状态轻微残留**
   经动作按钮（编辑/删除）关闭自身时，`closeSelf()` 只把 `translateX` 归零、清 `openedRef`，但未 `setOpenSwipe(null)`。若用户随后滑其他行，旧 `id` 仍残留在总线。视觉无碍（因 `translateX===0` 不二次收），但状态不严谨。
   **建议**：`closeSelf()` 内补 `setOpenSwipe(null)`。

3. **`lib/i18n.ts` — 字典完整性无校验**
   `Dict` 接口定义 64 key，但 `I18N.zh` / `I18N.en` 任一语言漏 key 会导致 `t(k)` 返回 `undefined` → 界面渲染 "undefined"。无编译期/运行期保障。
   **建议**：启动时断言两字典 key 集合一致，失败抛错并告警。

4. **`lib/theme.ts` — 死代码（React Navigation 主题）**
   定义 `THEME` / `NAV_THEME`，全文零引用（工程用 expo-router + 自定义 `tokens.ts`，不走 RN Theme）。
   **建议**：删除整个文件。

5. **`components/ui/*`（31 个文件）— 死代码（rn-primitives 自动生成封装）**
   全部为 `@rn-primitives/*` 的 shadcn 风格包装，**业务代码（app/、components/、store/、lib/）零引用**——所有 import 仅发生在 `ui/` 目录内部互相引用。此为秒哒脚手架自动生成、但实际未被采用的组件库。
   **建议**：删除整个 `components/ui/` 目录（约 31 文件）。若担心个别组件后续复用，先确认引用率再保留。

## 三、建议问题（💭）

1. `components/ProSection.tsx:42` 用 `key={i}`：静态固定列表可接受，但非最佳实践。
2. `store/usePro.ts:64` 未清理的 `setTimeout(showToast, 1800)`：组件卸载后可能触发 React 18+ 的 setState 警告。建议用 ref + 清理函数。
3. `lib/iap.ts`、`components/modals/TaskFormModal.tsx` 的 `any`：多为动态 `import()` 的类型，已加 eslint-disable，可接受；若想收紧可给 `react-native-purchases` 写最小 `type` 声明。
4. `lib/demoData.ts:27` `createdAt` 用 UTC ISO（`...Z`），与本地 `YYYY-MM-DD` 日期混存；当前靠字符串比较保证排序安全，但语义不一致，建议统一本地序列化。
5. `components/Sheet.tsx` center 模式（确认/庆祝弹层）默认 `backdropClosable=true`：删除确认弹层点遮罩会关闭（等同取消）。属设计取舍，建议评估删除确认是否应禁遮罩关闭。
6. `lib/scoring.ts:18` `uid()` 同毫秒理论碰撞：顺序保存场景几乎不可能，仅提示。
