# Seeora 本地验证流程说明（打包前门禁）

> 目的：在花掉一次 **EAS Build**（Expo 官方云构建服务，按次计费）额度之前，先在本地把「路由 404 / 编译失败 / 渲染崩溃 / 单测失败」这几类问题拦下来，避免无效打包。

本流程是 `npm run build:ios` / `build:android` 的**前置硬闸门**：本地校验不过，云端构建根本不会被触发。

---

## 一、环境前提

- **Node.js**：项目使用 pnpm（项目内 `node_modules` 由 pnpm 管理），请保持与 CI 一致的 Node 大版本。
- **包管理器**：`pnpm install` 已装好依赖（含 `jest-expo`、`@testing-library/react-native`、`react-test-renderer` 等校验依赖）。
- **eas CLI（仅真正打包时需要）**：`npm i -g eas-cli`（全局安装）。本地校验阶段不需要它；只有校验全过、`npm run build:ios` 走到最后一步才会调用。
- **Windows 没有 iOS 模拟器（Simulator）**：这是客观限制。本流程用三道等价的本地闸门来替代「真机/模拟器加载」：
  1. **Metro 打包检查**（见下方 ROUTE-MANIFEST / BUNDLE）——与 EAS 云端**同源**的 bundling（打包编译），能抓出大部分「云端才炸」的编译问题；
  2. **路由死链静态核对**（ROUTE-MAP / ROUTE-LINK）——抓「导航到的路径磁盘上没有对应页面」；
  3. **jest 渲染冒烟（RENDER-SMOKE）**——用 `react-test-renderer` 把 App 真正渲染一遍，抓「运行期崩溃 / 空屏 / Unmatched Route（路由未匹配/404 屏）」。

---

## 二、三条核心命令

```bash
# 1) 完整本地校验（推荐每次提交/打包前跑）
npm run check-local

# 2) 快速校验：跳过 iOS 导出（BUNDLE 步），约省 1~2 分钟
npm run check-local -- --quick

# 3) 离线/端口被占用时：跳过 expo start 清单核对（ROUTE-MANIFEST 步）
npm run check-local -- --no-server

# 4) 带门禁打包（iOS）—— 内部等价于：先跑 check-local，过了再 eas build
npm run build:ios

# 5) 带门禁打包（Android）
npm run build:android
```

> `check-local` 支持的组合参数：`--quick`（跳过 BUNDLE）、`--no-server`（跳过 ROUTE-MANIFEST）、`--port 8099`（指定本地开发服务端口，默认 8099）。
> `build:ios` / `build:android` 也支持把参数透传给内部 check-local，例如 `npm run build:ios -- --quick`。

## 三、校验内容（check-local 做了什么）

`npm run check-local` 依次跑 6 步 + 1 个渲染冒烟，全部输出为 ASCII（避免 Windows PowerShell 5 控制台中文乱码）：

| 步骤 | 名称 | 检查内容 | 失败含义 |
|------|------|----------|----------|
| 1/6 | **ROUTE-MAP** | 按 expo-router 规则把 `src/app` 文件树解析成 URL 表；校验根路径 `/` 必须存在、无两文件抢同一 URL、每个路由文件都 `export default` | 根路径缺失（正是 2026-10-17 那次 TestFlight Unmatched Route 事故的成因） |
| 2/6 | **ROUTE-LINK** | 扫描 `src/` 下所有代码里的 `"/xxx"` 字面量（`router.push` / `Link href` / `Redirect` / `go()` 等），逐一核对能否对上真实页面 | 存在拼错或已删除的死链（如 `/todayyy`） |
| 3/6 | **ROUTE-MANIFEST** | 起一次 `expo start`（本地开发服务），读 expo-router **自己生成**的路由清单，与第 1 步结果逐条比对（权威证据，非手写规则） | 两份路由表对不上（多为第 1 步解析规则偏差，或 expo start 端口被占用） |
| 4/6 | **TYPES** | `npx tsc --noEmit` 必须 0 错误 | TypeScript 类型错误 |
| 5/6 | **TESTS + RENDER-SMOKE** | 先跑项目原有单测（`jest.config.mjs`，纯函数），再跑渲染冒烟（`jest.check-local.config.mjs`，把 App 渲染一遍） | 单测失败，或**首页落 Unmatched Route 屏 / 空屏** |
| 6/6 | **BUNDLE** | `npx expo export --platform ios` 必须编译成功（打包期才炸的问题在这里暴露） | 打包编译失败（`--quick` 时跳过） |

**RENDER-SMOKE（渲染冒烟）4 个用例**：
1. ① 首页 `/` 可渲染，且不落 **Unmatched Route** 屏；
2. ② 默认落地页 `/today` 渲染出实际内容（防空屏假绿，断言渲染出 ≥3 段文案）；
3. ③ 对照实验：故意访问不存在的路径，必须落 Unmatched Route——证明 ① 的「没落 Unmatched」是真的检测到了，而不是查询写错（自证非假绿）；
4. ④ 全部路由逐个渲染（**advisory 只告警不阻断**：jest 环境缺原生模块可能让个别路由假失败，不影响真机，需结合 BUNDLE 步人工复核）。

## 四、成功 / 失败的判断标准

**唯一权威信号是最后两行：**

```
================ SUMMARY ================
  ROUTE-MAP                PASS   ...
  ROUTE-LINK               PASS   ...
  ROUTE-MANIFEST           PASS   ...
  TYPES                    PASS   ...
  RENDER-SMOKE             PASS   4 passed, 0 failed ...
  TESTS                    PASS   85 passed, 0 failed
  BUNDLE                   PASS   ...
-----------------------------------------
  RESULT: BUILD ALLOWED        ← 通过，可打包
```

- **通过**：`RESULT: BUILD ALLOWED`，且退出码为 `0`（`echo $LASTEXITCODE` 为 0）。此时 `npm run build:ios` 才会继续调用 eas。
- **失败**：`RESULT: BUILD BLOCKED`，退出码非 0；并会**逐条列出标 FAIL 的项**。此时 `npm run build:ios` 会打印「══ 本地校验未通过，已阻止 EAS 云端构建 ══」并**直接退出，不触发任何云端构建**。

> 在 Windows PowerShell 里查看退出码：`echo $LASTEXITCODE`（0 = 通过，非 0 = 失败）。

## 五、常见失败怎么处理

| 失败项 | 典型现象 | 排查方向 |
|--------|----------|----------|
| ROUTE-MAP | `MISSING root route "/"` | 根路径没有页面文件。`src/app/index.tsx` 必须存在（哪怕是 `<Redirect href="/today" />`）。这正是本工程 2026-10-17 事故的修复点。 |
| ROUTE-MAP | `DUPLICATE URL /xxx` | 两个文件映射到同一 URL（如 `app/foo.tsx` 与 `app/foo/index.tsx`），删掉多余的一个。 |
| ROUTE-LINK | `"/xxx" does not match any route` | 代码里导航到了不存在的路径。确认是拼写错误还是路由文件被改名/删除（注意：`src/lib/__tests__/` 下的测试样例字符串已被排除，不会误报）。 |
| ROUTE-MANIFEST | `route manifest was not regenerated` | `expo start` 没在 120s 内起来，多半是端口被占用。换端口：`npm run check-local -- --port 8101`，或离线时用 `--no-server` 跳过本步。 |
| TYPES | `tsc --noEmit` 报错 | 按报错文件:行号修类型；不要为了过校验而 `any` 糊弄。 |
| RENDER-SMOKE ① | 落到了 Unmatched Route 屏 | 首页渲染链路上某处崩了（最常见是原生模块在 jest 环境缺 mock）。看 ① 用例的失败详情定位。 |
| RENDER-SMOKE ④ | advisory 列出某路由失败 | 多为 jest 缺原生模块，不影响真机；以 BUNDLE 步（真实打包）结果为准。 |
| TESTS | 单测失败 | 跑 `npm test` 看具体用例；先修业务代码，不要动校验脚本。 |

## 六、重要提醒：本地校验 ≠ 真机验证

check-local 只验证「能编译、能渲染、路由对得上」。它**永远不真的看屏幕**。发 TestFlight 之前，仍需在真机安装构建版并确认：

1. App 打开落在 **Today** 页，而不是 Unmatched Route 屏；
2. 底部三个 Tab（History / Today / Settings）能切换；
3. 点「+」能打开习惯表单；
4. 打卡有 confetti（彩屑动效）；
5. Settings → About 能打开；
6. 没有空白屏 / 黑屏。

任何一项异常：截图并回报。

## 七、已知告警（非阻断，供关注）

- **`[Layout children]: No route named "settings" exists in nested children`**：来自 `(tabs)/_layout.tsx` 的 `<Tabs.Screen name="settings" />` 与 `settings/`、`settings/index`、`settings/about` 的路由树命名存在不一致。目前不影响渲染（Today / Settings 都能正常打开），但属于配置异味，建议后续把 Tabs 的 screen name 与目录结构对齐，避免埋雷。
- **RENDER-SMOKE ④ 个别路由 advisory 失败**：jest 无原生运行时，含未懒加载原生能力的路由可能假失败，属预期内噪声。

## 八、文件清单（本流程新增/改动，未改动任何业务页面与路由文件）

- `scripts/check-local.mjs` —— 主校验脚本（6 步 + 渲染冒烟入口）
- `scripts/prebuild-check.mjs` —— `build:ios` / `build:android` 的打包前门禁（校验不过绝不调 eas）
- `scripts/lib/route-inventory.mjs` —— 路由清单与死链检测核心模块（供 RENDER-SMOKE 生成 JSON）
- `scripts/checks/routes-render.test.tsx` —— RENDER-SMOKE 的 jest 渲染冒烟用例
- `scripts/checks/expect-matchers-shim.js` —— `expect/build/matchers` 兼容垫片（expo-router 55 与 expect 30 的版本错位）
- `jest.check-local.config.mjs` —— RENDER-SMOKE 专用 jest 配置（独立，不干扰 `npm test`）
- `package.json` —— 新增 `check-local` / `check-local:quick` / `build:ios` / `build:android` 脚本与校验依赖
- `docs/本地验证流程说明.md` —— 本文件
