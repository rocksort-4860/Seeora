## 4. 首屏关键代码（供核验者核对逻辑）

### 4.1 根布局 `src/app/_layout.tsx`（含内置 DIAG 二分开关）

```tsx
import "../global.css";
import React from "react";
import { View, Text } from "react-native";
import { Linking } from "react-native";
import { GestureHandlerRootView } from "react-native-gesture-handler";
import { StatusBar } from "expo-status-bar";
import { PortalHost } from "@rn-primitives/portal";
import { AppProvider, useApp } from "@/store/app";
import { ToastHost } from "@/components/Toast";
import { ConfettiHost } from "@/components/Confetti";
import { ModalHost } from "@/components/ModalHost";

// ── 崩溃红线 #4：Linking 兜底 ── 裸 scheme URL（seeora://... 无后续路径）在 expo-router 启动期会触发崩溃；中性化为 null
const _orig = Linking.getInitialURL;
Linking.getInitialURL = async () => {
  const u = await _orig();
  return u && u.startsWith("seeora://") && u.replace("seeora://", "").replace(/\/$/, "") === "" ? null : u;
};

// ── 冷启动崩溃「二分诊断」开关（仅排查用；正常构建不设）──
const DIAG = process.env.EXPO_PUBLIC_DIAG === "1";
const STAGE = Number(process.env.EXPO_PUBLIC_DIAG_STAGE ?? "0");

function ThemedStatusBar() {
  const { dark, colors } = useApp();
  return <StatusBar style={dark ? "light" : "dark"} backgroundColor={colors.bg} />;
}

export default function RootLayout({ children }: { children: React.ReactNode }) {
  if (!DIAG) {
    return (
      <GestureHandlerRootView style={{ flex: 1 }}>
        <AppProvider>
          <ThemedStatusBar />
          {children}
          <ToastHost />
          <ConfettiHost />
          <ModalHost />
          <PortalHost />
        </AppProvider>
      </GestureHandlerRootView>
    );
  }
  // DIAG 模式：STAGE -1 只显示 "BARE STAGE -1"；STAGE 0/1/3/4 逐级叠加组件
  if (STAGE <= -1) {
    return (<View style={{ flex: 1, alignItems: "center", justifyContent: "center", backgroundColor: "#fff" }}>
      <Text style={{ fontSize: 18, color: "#111" }}>BARE STAGE -1</Text></View>);
  }
  const withStatusBar = STAGE >= 1;
  const withGesture = STAGE >= 3;
  const withOverlay = STAGE >= 4;
  const inner = (<>
    {withStatusBar && <ThemedStatusBar />}
    {children}
    {withOverlay && (<><ToastHost /><ConfettiHost /><ModalHost /><PortalHost /></>)}
  </>);
  if (withGesture) {
    return (<GestureHandlerRootView style={{ flex: 1 }}><AppProvider>{inner}<DiagBadge stage={STAGE} /></AppProvider></GestureHandlerRootView>);
  }
  return (<AppProvider>{inner}<DiagBadge stage={STAGE} /></AppProvider>);
}
```

`node_modules/miaoda-expo-devkit/dist/babel/preset.js`（第 36–67 行，已确认 `excludePaths` 只影响开发期调试插件）：
```js
function presetExpoDevkit(api, options = {}) {
  const isDev = api.env("development");
  const isWeb = api.caller((caller) => caller?.platform === "web");
  const { rootDir = process.cwd(), excludePaths = [], lucide = {} } = options;
  const workletsPlugin = require.resolve("react-native-worklets/plugin");
  return {
    presets: [
      ["babel-preset-expo", { jsxImportSource: "nativewind", worklets: false, unstable_transformImportMeta: true }],
      "nativewind/babel"
    ],
    plugins: [
      ...lucide !== false ? [[require.resolve("./plugin-lucide-react-native"), lucide]] : [],
      ...isDev ? [[require.resolve("./plugin-jsx-source"), { rootDir, excludePaths }]] : [], // ← excludePaths 仅此处用
      ...!isWeb ? [[workletsPlugin]] : [],   // ← worklets 对所有原生文件无条件注入
      ...isWeb ? [[workletsPlugin, { omitNativeOnlyData: true }]] : []
    ]
  };
}
```

## 5. 根因方向（按优先级，供交叉核验）

> 两个包都白屏 + 编译期无错 + 静态树无同步抛错 + 无阻塞预加载 → **最可能是原生层启动期崩溃**（iOS 26 / RN 0.83 新架构的已知雷区）。

| # | 方向 | 优先级 | 说明 / 线索 |
|---|---|---|---|
| 1 | **iOS 26 + RN 0.83 新架构冷启动原生崩溃（SIGABRT / turbomodulemanager 队列）** | 🔴 最高 | RN 0.81+ 在 iOS 26 上有已知冷启动 SIGABRT（栈：`turbomodulemanager` 队列 → `ObjCTurboModule::performVoidMethodInvocation`）。App 启动即崩但用户看到的是「白屏」而非崩溃弹窗。本项目 RN 0.83.2 正好中招。历史上为修 Xcode 26 `-Werror` 编译坑打过 `withExpoModulesCoreWerrorFix` 补丁，**但那是编译期，不解决运行时冷启动崩溃**。 |
| 2 | **reanimated v4 / worklets 原生模块运行时桥接** | 🔴 高 | 即便 babel 注入正确，`Confetti.tsx` 顶部 `import "react-native-reanimated"` 会在 bundle 加载阶段触发 reanimated 模块初始化；reanimated 4 在 RN 0.83 新架构下的原生端（pods）初始化时机问题可能导致启动早期崩溃。`app.json` 已配 `autolinking.ios.buildFromSource: [reanimated, worklets]` + `buildReactNativeFromSource: true`。 |
| 3 | **自定义 config 插件的运行时副作用** | 🟡 中 | `withTurboModuleFix` / `withFmtConstevalFix` / `withCrashReason` 是为修 Xcode 26 编译而写，可能改了原生配置（如 `OTHER_CFLAGS`、模块初始化顺序）导致编译过但运行崩。需逐一核验这些插件到底改了什么原生设置。 |
| 4 | **expo-router 路由解析 / 入口加载** | 🟡 中 | root=`src/app`，入口 `expo-router/entry` → `_layout.tsx` → `index.tsx`(Tabs)。编译期路径 OK，但运行时路由表若抛错（如某路由文件缺失/循环）会白屏。 |
| 5 | **lucide 图标渲染异常** | 🟢 低 | 见 4.5；通常是局部报错，非全白，作为兜底排查。 |
| 6 | **expo-splash-screen 未隐藏** | 🟢 低 | grep 0 命中 `preventAutoHideAsync` → splash 不会卡；但若原生 splash 配置异常仍可能卡白，列为低优先。 |
| 7 | **AsyncStorage / 原生 pod 链接** | 🟢 低 | `@react-native-async-storage/expo-with-async-storage` 较新，需确认 pod 正确链接（但 `sget` try/catch 已兜住读取异常）。 |

## 6. 给交叉核验者的动作清单（按性价比排序）

1. **【第一优先】抓真机崩溃日志（最硬证据）**
   - iPhone：`设置 → 隐私与安全性 → 分析与改进 → 分析数据`，找 `Seeora-<日期>_<时间>.ips` 崩溃报告（或 `Jetsam` 低内存报告）。
   - 有 Mac：Xcode → `Window → Devices and Simulators` → 选设备 → `View Device Logs`；或 Mac「控制台（Console）」app → 选设备 → 搜 `Seeora`。
   - **重点看崩溃类型**：`EXC_CRASH (SIGABRT)` + 栈含 `turbomodulemanager` / `RCTTurboModule` / `ObjCTurboModule` → 命中方向 #1；栈含 `REA` / `reanimated` / `worklets` → 命中方向 #2。
   - ⚠️ 说明：此前误判「白屏大概率无崩溃日志」。若属原生 SIGABRT，则**一定**有 `.ips` 日志，请优先查。

2. **【第二优先】本地 `expo start` 跑 Dev 客户端 / 模拟器**
   - 在 Mac 上 `cd native && npx expo start`，用 iOS 模拟器或 Dev Build 打开，**Dev 模式会显示红屏报错栈**（Release/TestFlight 是白屏，Dev 是红屏，这是定位 JS 层错误最快的方式）。

3. **【第三优先】启用内置 DIAG 二分诊断（需重打包，需授权）**
   - 机制已在 `_layout.tsx` 内置（见 4.1）：设 `EXPO_PUBLIC_DIAG=1` 与 `EXPO_PUBLIC_DIAG_STAGE`（-1/0/1/3/4）分级渲染。
   - 手机看到哪一级变白屏，就能锁定崩在哪一段：
     - `STAGE -1` 只显示 `BARE STAGE -1` → 证明 App 能启动（问题在 JS/路由层）
     - `STAGE 0` 起逐级叠加 StatusBar / GestureHandler / AppProvider / Overlay → 圈定范围
   - **此动作属「构建」，目前按用户铁律必须显式授权才执行**。

4. **【第四优先】核验自定义 config 插件**
   - 逐个读 `native/plugins/crashReason/withCrashReason`、`turboModuleFix/withTurboModuleFix`、`withFmtConstevalFix`、`withExpoModulesCoreWerrorFix` 的源码，确认它们对 `ios` 原生配置（build settings、pods、初始化顺序）的实际改动，排查运行时副作用（方向 #3）。

5. **【对照】查 EAS 构建日志**
   - `eas build:view <id> --json` 取 `logFiles` URL（签名 900s 过期），用 Node `zlib.brotliDecompressSync` 解码查看是否有运行时警告（gzip/zlib/inflate 会失败）。

## 7. 已知相关历史（避免重复踩坑）

- **Xcode 26 `-Werror` 编译坑（已修）**：`expo-modules-core/ios/Worklets/EXJavaScriptSerializable.mm:52` 报 `[−Werror,−Wreturn-type]`，`EXJavaScriptSerializable.mm` 的 switch 无 `default:`。已用 config 插件 `withExpoModulesCoreWerrorFix.js`（`withDangerousMod('ios')`，prebuild 阶段补 `default: return EXSerializableValueTypeUndefined;`）解决，build 10 已成功出包。**此修复仅解决编译期，与本次运行时白屏是两件事。**
- **iOS 26 冷启动 SIGABRT（已知雷，方向 #1）**：见 `rn-ios26-turbomodule-crash-fix` 相关经验——RN 0.81+ 在 iOS 26 Release 包冷启动可能 SIGABRT。本项目 RN 0.83.2 属此范围，需重点排查。
- **打包铁律**：用户明确要求「未经显式授权不得重打包」。任何 DIAG 诊断包、重新构建动作都需先取得授权。
