## 1. 现象与待定性（v1 描述已订正）

- **v1 原描述**："整屏纯白、不显示任何 UI、不自动回桌面" —— 经第三方核验，这一描述是**推测而非已确认事实**，且"不自动回桌面"与"原生 SIGABRT 崩溃"互相矛盾（真 SIGABRT 会毫秒级踢回桌面）。
- **订正为中性**：用户打开 App 后停在白屏（**进程是否存活未确认**）。
- **【零成本·第一优先 3 问】**（直接问用户，不重打包）：
  1. 是"一直停在白底"，还是"先白底一会儿、然后自己滑回桌面"？
  2. 双击 Home / 上滑停驻，App 卡片是**有缩略图**（进程活着）还是**空白卡片**（进程已死）？
  3. 打开后 30 秒内，是否曾经回桌面一次？
  → 答案二分：**进程死**（→ 原生崩，去抓 `.ips`）/ **进程活**（→ JS 渲染失败 或 splash 没隐藏，走 NativeWind / expo-router / splash 方向）。

### 4.3 crashReason 信号处理器（`plugins/crashReason/withCrashReason.js` 关键段）

```c
// 第 58–67 行：捕获 SIGABRT
static void CR_signal_handler(int sig) {
  if (g_CR_handled) return;
  g_CR_handled = 1;
  char label[64];
  snprintf(label, sizeof(label), "[signal %d]", sig);
  CR_capture_backtrace(label);
  signal(sig, SIG_DFL);   // 恢复默认行为
  raise(sig);             // 重新触发 → 进程真正终止，系统生成 .ips
}
// 第 73–79 行：+load 注册
+ (void)load {
  NSSetUncaughtExceptionHandler(&CR_objc_handler);
  signal(SIGABRT, CR_signal_handler);
  signal(SIGSEGV, CR_signal_handler);
  signal(SIGBUS, CR_signal_handler);
  signal(SIGILL, CR_signal_handler);
}
```

> 结论：crashReason **不会吞掉 .ips**（它 re-raise）；且额外把崩溃栈写到 `Documents/crash_reason.txt` 和 `NSUserDefaults["crash_reason"]`，这是比 `.ips` 更易读取的诊断源（需 Mac 或文件导出读 App 沙盒）。

### 4.4 turboModuleFix 修复语义（`plugins/turboModuleFix/withTurboModuleFix.js` 注释第 5–24 行摘要）

> 修复 iOS 26 + RN 新架构 TurboModule 冷启动 SIGABRT：RN 在 `performVoidMethodInvocation`/`performMethodInvocation` 的 `@catch` 里把 NSException 转成 `jsi::JSError` 并 `throw/@throw`，跑在后台 `turbomodulemanager` 队列、无 JS 捕获 → rethrow 到无人监听队列 → `abort()`。本插件把 `throw convertNSExceptionToJSError(...)` 改为 `RCTLogError + return`（不再 abort）。RN 0.83.2 的 `RCTTurboModule.mm` 含 `convertNSExceptionToJSError`（grep 命中）→ 补丁目标存在。

### B-2 crashReason 不吞日志（反而多诊断源）
- `withCrashReason.js` 第 58–67 行 `CR_signal_handler`：`CR_capture_backtrace` 后 `signal(sig, SIG_DFL); raise(sig);` → 进程终止、系统生成 `.ips`。

### B-3 withTurboModuleFix 是修复非元凶
- 注释第 5–24 行：修复 iOS 26 TurboModule `performVoidMethodInvocation`/`performMethodInvocation` 的 `@catch` 把 NSException 转 `jsi::JSError` 后 `throw/@throw` → 后台队列无人捕获 → `abort()`。本插件改 `throw convertNSExceptionToJSError` → `RCTLogError + return`。
- RN 0.83.2 `node_modules/react-native/ReactCommon/react/nativemodule/core/platform/ios/ReactCommon/RCTTurboModule.mm` 含 `convertNSExceptionToJSError`（grep 命中）→ 补丁目标存在、有生效条件。
- **结论**：若补丁生效，iOS 26 TurboModule 崩应已被吞（RCTLogError 非 abort）。白屏若仍在 → 要么补丁没真打上（查 EAS 日志 #3/#8），要么不是 TurboModule 崩。
